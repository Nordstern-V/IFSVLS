# 视觉识别排查与回归验证 Skill

**队内审阅稿**：请先给队长核对选题、使用方法和案例证据，再决定是否作为比赛技能包的一部分提交。

## 一、这是什么

这是从本队视觉项目与 AI 协作排查中提炼的一套工作方法，帮助开发者面对以下问题时组织证据：首次识别慢、物体移动后漏框、背景误框，以及修改后不同物体表现不一致。

使用者可以让支持技能文件的 AI 阅读 `SKILL.md`，也可以直接复制 `prompt.md` 的提示词。AI 应协助检查实际代码和资料，并按测试结果给出结论；技能本身不会自动修复软件，也不能代替现场测试。

## 二、适用范围和所需资料

- **适用**：已具备代码或诊断资料的现场学习识别、目标检测、目标跟踪等视觉系统；不依赖某个具体物体或特定模型。
- **所需资料**：基线代码和运行环境、对应学习阶段的数据、诊断原图或录像，以及已知的目标类别和出现区间。做前后比较时，还需要候选代码和相同的测试条件。
- **资料不足时**：先列出缺失项；没有类别标注、原始图像或板端实测记录，就不能推算准确率、还原真实摄像头输入或声称上板性能。
- **资料保护**：只读现有学习数据，禁止覆盖已有学习库；修改程序前备份，并在隔离候选中测试。是否启动设备或修改部署由项目实际授权决定。

## 三、怎么使用

1. 先核对基线、学习数据、诊断图和录像是否属于同一学习阶段，记录版本与数据的校验信息。
2. 让 AI 依次检查候选生成、分类与背景检查、身份核验、边界、跟踪以及正式显示；区分未开始、超时未完成和明确拒绝。
3. 用同一组输入、时长和配置比较基线与候选，分别记录首次**正确类别**正式出框、漏框及恢复、学习区域位置、背景误框、目标离开后的残留和运行速度。
4. 将结果写入 `result_template.md`；没有逐帧标注就不填写准确率或召回率。若测试不完整、有退化或结果波动，明确保留失败，不能宣称修好了。

需要复制给 AI 的完整提示见 `prompt.md`。换到其他项目时，将输入、数据绑定和检查环节替换为该项目实际情况；若没有学习库，改为记录模型版本与测试集。

## 四、文件说明

| 文件 | 内容 |
|---|---|
| `SKILL.md` | 供 AI 读取的技能入口和操作边界。 |
| `prompt.md` | 可直接复制使用的中文提示词。 |
| `result_template.md` | 输入绑定、测试条件、结果和失败记录模板。 |
| `case_study.md` | 本队真实案例、观察到的结果和限制。 |
| `evidence/` | 从已有回归记录提取的汇总数据及来源校验信息。 |

本包不包含程序、学习库、诊断图片、屏幕录像或自动测试脚本；独立复现需使用相应工程和获授权的数据。`evidence/` 是汇总，不是逐帧标注或完整原始日志。

## 五、已有验证与限制

本队曾用匹配学习阶段的两类原图和视频、单类水杯资料、背景控制及静态切换序列开展离线对照。具体结果及失败记录见 `case_study.md`。

这些测试说明该排查流程能够记录并暴露部分回归风险，**不证明**此 Skill 能对所有新物体稳定有效，也不证明板端帧率、识别准确率或背景误框已经达标。尚未完成其他队伍独立复用验证；屏幕录像带旧框与遮挡，静图硬切换不能替代真实连续运动。
