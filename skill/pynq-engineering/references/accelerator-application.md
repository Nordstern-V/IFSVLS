# 加速器与应用边界

## 先写清输入输出契约

接入 TCU 或其他加速器前，从实际模型、编译产物和驱动确认：图像尺寸、通道顺序、dtype、预处理运算顺序、量化/定点格式、lane padding、输入输出名称、分段地址和真实有效维度。

不要顺手将已有表达式改成“常见标准公式”；例如本例实际使用 `x / 255 - MEAN / STD`，不是 `(x / 255 - MEAN) / STD`。改变后必须验证模型兼容，不能只凭两式看起来相近判断。

分别核对 AXI DMA 的数据宽度、最大传输长度、对齐、缓存一致性、启动/等待顺序与错误状态。对齐补零一般应按“余数为零时不额外补一整块”的规则计算，例如 `(-length) % alignment`，但长度单位必须与接口保持一致。

模型输出可能分散在多个编译段，驱动返回值也可能已拼接；先确定两者再抽取特征。返回元素数量恰好等于某个网络维度，不证明从内存读取的位置或顺序正确。

## 分级验证

1. 用小型确定性输入（梯度、单像素扰动等）验证长度、有限值、分段和重复一致性。
2. 需要模型等价结论时与可信参考比较，注明预处理、定点误差和容差，不能以重复一致代替等价。
3. 最后用摄像头 ROI、真实类别和统一条件评估准确率/背景误检/时延；主机 fake TCU 只能验证协议与状态逻辑。

在整机中复用单一模型/加速器实例；不支持重入的设备由一个工作者串行提交，学习、手动预测、扫描和数字任务统一调度。请求带不可变 ROI 副本和代次，输出只提交给仍有效的任务。

## 应用模式与数据不要混用

本例 A/B、数字和算符是三套独立数据。模型和 TCU 可以共用，不代表均值、类别、颜色统计或预测历史可以共用。新模式应明确哪些状态继承、重置、持久化，哪些按钮只管理特定数据。

固定类别 ID 与可编辑显示名称分开；用户 Enter 只是确认名称，若采样随后失败，名称不应覆盖旧类别。成功后将新特征及其名称一起提交，旧 NPZ 无名称字段时使用默认显示名。加载不需要信任 pickle。

手动分类与自动扫描可采用不同判据。本例 B 手动走 NCM，SCAN 走余弦 Top-k、类别分差、背景/尺寸筛选、NMS 和跨周期确认，不能强行合并门限。NCM 类间分数和余弦匹配分数不应统一宣传成真实正确率。

数字/算符先从原尺寸 ROI 提取字形，再变为模型输入；不能先把宽松 ROI 缩成 32×32 丢失细节后再当原图处理。支持库和现场 ROI 必须使用兼容预处理版本与后端，OpenCV 和 NumPy fallback 不必然完全等价。

存入计算式时，仅接受屏幕已经显示、当前仍有效、类型/顺序一致且未被消费的稳定候选；不要把识别后台更新的另一个值偷偷存入。FREEZE、READY 和 Xn/OPn 的条件由实际 UI 定义，不能只观察最高分类概率。

## 回退与兼容

先确定用户要恢复的范围和参照目录，比较模块/方法与数据契约；只替换该范围，并保留明确要求保留的键盘、数字与计算器功能。历史文件仍被导入或旧元数据仍保留，不等于历史算法仍在活动路径中。

需要旧版兼容时做实际加载及行为比较；不通过删除所有缓存来掩盖格式错误。只有模型/预处理/特征契约改变时，说明对应支持库为什么需要重建。
